## 0. 结论摘要

当前策略不是“指标不够”，而是同一笔交易在多个阶段被重复解释：

1. 基础策略先计算多空分数；
2. 多周期处理再次加减分并改变动作；
3. 入场价格和盈亏比又转换成分数；
4. 多个行情状态字段同时参与方向、风险、开仓、加仓和出场；
5. 开仓同时存在“按止损风险定仓”和“按固定保证金定仓”两条路径；
6. 支撑压力不足时，止盈逻辑可能补出一个更远的理论目标；
7. 加仓、轮动和退出分支较多，但总风险和行为优先级不够统一。

本次建议不是再增加一套模型，而是把交易链收敛为：

```text
合格标的池
  → 单一行情上下文
  → 固定的机会评分
  → 一个主入场区和一个失效位
  → 入场门槛逐项检查
  → 按止损风险统一定仓
  → 两阶段退出
```

### 0.1 本次最优先的四项改动

1. **评分冻结**：`setup_score` 只表示机会强度，同一根已收盘 K 线内不因实时价格改变；入场位置和盈亏比不再加分。
2. **统一风险定仓**：删除固定保证金路径绕过风险预算的可能，所有首仓和加仓均先计算最大亏损，再计算数量和保证金。
3. **真实目标约束**：没有有效结构目标，或扣除成本后的计划盈亏比不足，则等待更好的价格；不得为了放行而生成更远的理论 TP2。
4. **暂缓自动加仓和轮动**：在首仓总风险、加仓后总风险和退出状态统一之前，不让复杂功能扩大错误。

### 0.2 已完成能力，不重复建设

以下能力应保留并继续使用，不在本 PRD 中重新设计：

- 多空完全同分时保持中立，不默认偏多；
- `direction_state`、`crowding_state`、`liquidity_state`、`system_risk_state` 四个独立状态；
- 滚动基线、阈值自适应、状态滞回和持续确认；
- 流动性异常、系统性风险异常对新开仓的拦截。

后续只做“决策权迁移和旧字段退役”，不再增加第五个综合行情标签。

## 2. 需求说明

### 2.1 改动背景

当前策略已经具备较丰富的指标和多周期数据。继续增加指标、参数或币种特例，会产生三个反效果：

1. 同一市场事实被多次加分，历史拟合增强，样本外稳定性下降；
2. 高分不一定等于当前价格适合开仓；
3. 风控逻辑分散后，即使每个局部判断合理，组合后的最大亏损也可能不一致。

因此，本次目标不是“让更多信号通过”，而是让系统能够稳定回答四个问题：

1. 这个标的现在是否值得观察？
2. 当前方向是否明确，机会本身是否足够好？
3. 当前价格是否真的值得下单？
4. 即使判断错误，账户最多亏多少？

### 2.2 设计约束

1. 不新增技术指标，不引入机器学习模型。
2. 不新增币种专属参数。
3. 配置参数总数原则上不增加；新增一个参数必须合并或淘汰至少一个旧参数。
4. 一个概念只能有一个决策权威：
   - 一个行情上下文；
   - 一个机会分；
   - 一个主入场区；
   - 一个结构失效位；
   - 一个净计划盈亏比；
   - 一个组合风险入口。
5. 指标可以在不同阶段复用，但同一证据只加一次分。
6. 开仓门槛采用逐项通过，不再用“高分抵消风险否决”。
7. 胜率是结果指标，不是单独优化目标；验收以净期望、回撤和风险违规为主。

### 2.3 改动点

#### R1：标的池收敛

标的池只保留四类硬准入条件：

1. 交易所状态为可交易的 USDT 永续合约；
2. 24 小时成交额达到现有最低要求；
3. 实时流动性状态为 `NORMAL`，买卖价差和数据新鲜度合格；
4. 4H、1H、15m 所需数据完整且已收盘。

准入后只按 24 小时成交额形成观察池，不再增加多因子“标的池综合分”。

实施时按用户最终确认覆盖原 Top20 建议：先取交易所 24 小时成交额降序 Top80，再保留闭合 K 线 `setup_score > 65` 的标的。Top80 内不按评分重新排序；评分只决定是否进入合格池，实际开仓候选仍可按机会分排序。`symbols_mode: top20_usdt_perp` 和 `AUTO_TOP50` 暂作为兼容名称保留，不再代表真实池大小，后续经过一个兼容版本再统一命名。

硬编码排除名单改为一个显式、可审计的包含/排除配置；BTC、ETH 是否仅作为市场基准或同时可交易，需要由同一个配置表达。

#### R2：行情判断只有一个权威

统一使用已经实现的 `market_context`：

| 时间周期/状态 | 唯一职责 |
|---|---|
| 1D | 只作大级别风险背景，不直接精确择时 |
| 4H | 决定允许做多、允许做空或中性 |
| 1H | 识别具体交易结构和触发 |
| 15m | 只优化执行位置，不推翻 4H 方向 |
| `crowding_state` | 判断拥挤和反向挤压风险 |
| `liquidity_state` | 判断当前能否可靠成交 |
| `system_risk_state` | 决定是否暂停新增风险 |

旧 `regime`、`trend_state`、`risk_state` 在兼容期继续输出，但不得继续作为另一套独立决策源。完成影子对比后，内部读取全部迁移到 `market_context`。

#### R3：评分只表达机会强度

建立唯一的 `setup_score`，范围固定为 0～100。

评分仍保留 EMA、VWAP、布林、KC，因为它们既能反映方向和市场位置，也能构成入场区域；但处理方式是：

- 在评分阶段，它们只作为方向/结构证据，按证据族最多贡献一次；
- 在入场阶段，它们可以复用为价格区域，但不得再次给 `setup_score` 加分；
- 方向不一致时不能依靠其他高分把它抵消；
- 同一根已收盘 1H/4H K 线内，`setup_score` 不因实时价格变化而变化。

建议收敛为四个现有证据族，不新增指标：

| 证据族 | 表达内容 | 规则 |
|---|---|---|
| 方向与结构 | 4H/1H 结构、趋势和关键均线方向 | 同源证据取最强项，设族上限 |
| 价格位置 | EMA、VWAP、BOLL、KC 所在区域 | 只确认方向质量，不累计四次 |
| 触发 | 突破回踩、假突破、扫流动性后收回 | 同一 setup 只记一次 |
| 参与度 | 成交量、OI、资金费率和多空比 | 方向支持与拥挤风险分开，风险不加分 |

初期保持现有观察阈值 65、候选阈值 80，先改变分数职责，再通过走步验证调整阈值；不同时修改评分结构和阈值，避免无法归因。

#### R4：一个主交易计划

每个候选方向只允许输出一个逻辑上的主交易计划：

```text
side
setup_type
setup_score
primary_entry_zone
entry_trigger
invalidation_price
target_1
target_2（可缺省）
net_plan_r
vetoes
valid_until
```

为兼容现有代码，首期可继续使用现有 signal 字典传输，不要求立即新增大量类。重点是业务上只认这一份计划。

#### R5：建议入场位置和“入场优秀”

建议入场位置从“多个候选区任选命中”改成“一个主入场区”：

1. 优先选与当前 `setup_type` 直接对应的 1H/4H 结构区；
2. EMA、VWAP、BOLL、KC 如果彼此接近，合并为一个动态共振区，不分别输出为多个可开仓区；
3. 15m 只缩小主区或确认触发，不新增独立方向；
4. 主区在结构失效、超过有效期或 4H 方向改变后立即作废。

“入场位置优秀”必须同时满足：

1. 4H 方向允许该方向；
2. `setup_score >= 80`；
3. 实时可成交价格进入主区的优势侧；
4. 1H 触发已由收盘 K 线确认，15m 只做精度确认；
5. 没有任何硬否决；
6. 有真实结构止损和真实结构目标；
7. 扣除手续费、滑点及必要资金费后的 `net_plan_r` 达标。

优势侧继续复用现有分区思想：

- 多单只接受主区靠下的一侧；
- 空单只接受主区靠上的一侧；
- 初期沿用现有 60% 分区，不新增另一套参数；
- 特例分区后续应被统一规则替代，不再继续增加 setup 特例。

#### R6：否决项分层

只保留两类否决：

**硬否决：绝不允许高分抵消**

- 方向不明确或与计划相反；
- 流动性异常、系统风险异常、行情数据过期；
- 没有有效结构止损；
- 没有真实结构目标；
- 净计划盈亏比不足；
- 交易所最小数量、最小名义价值、价格精度无法满足；
- 账户风险预算不足。

**等待项：条件改善后可恢复**

- 价格未到主入场区；
- 触发 K 线尚未确认；
- 当前位于主区非优势侧；
- 主区已过期，需要重新生成计划。

开仓否决不得直接作为持仓退出理由。持仓退出只看该笔交易自身的失效位、硬止损和既定退出计划。

#### R7：支撑位和压力位收敛

只保留三类可执行价位：

1. 4H/1H 已确认摆动点或箱体边界；
2. 已突破并经过回踩确认的角色互换位；
3. EMA/VWAP/BOLL/KC 合并后的动态共振区。

采用固定优先级，不再为每个价位增加“强度分”“触碰次数权重”等新参数：

```text
4H 已确认结构
  > 1H 已确认结构
  > 突破回踩角色互换位
  > 动态共振区
```

价位在以下情况失效：

- setup 所属周期收盘有效穿越；
- 被价格反复穿越，已不能作为清晰边界；
- setup 到期；
- 4H 方向反转。

普通窗口最高/最低价只能作为候选锚点，不得在未确认时直接成为最终止损或目标。

#### R8：止损、止盈和净盈亏比

**止损**

1. 止损必须放在该 setup 的结构失效位之外；
2. 只使用一个缓冲：现有 ATR 结构缓冲与实时价差取更保守值；
3. 止损不由杠杆倒推，也不为了扩大仓位而缩窄；
4. 没有结构失效位则不开仓，不使用纯波动率兜底止损放行自动交易。

**止盈**

1. TP1 使用顺方向最近的有效对手结构；
2. TP2 使用下一个真实有效结构；
3. 找不到 TP2 时，不生成一个更远的理论目标；计划盈亏比按 TP1 作为剩余仓位的保守目标计算；
4. 开仓后可以让剩余仓位移动止盈，但未知 runner 收益不得计入开仓前盈亏比。

**净计划盈亏比**

沿用现有 TP1 比例 35%，剩余比例自动为 65%，删除三段比例相加不清晰的问题。

```text
预期净收益
= 0.35 × TP1距离
  + 0.65 × TP2距离（无TP2时用TP1）
  - 入场手续费
  - 分批出场手续费
  - 预计滑点
  - 预计持仓期间资金费

预期净亏损
= 止损距离
  + 入场手续费
  + 止损出场手续费
  + 预计不利滑点

net_plan_r = 预期净收益 / 预期净亏损
```

第一阶段建议把 **1.30R** 作为模拟盘候选门槛，原因是它接近当前系统入场质量首次加分点，行为冲击小于直接改到更高值；它不是永久结论，必须用样本外数据验证。

官方 Binance 文档表明标记价格接口同时提供标记价格、最新资金费率和下一次资金时间，因此只在预计持仓跨越结算时间时计入资金费，不需要再增加一组固定资金费参数：[Binance Mark Price and Funding Rate](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Mark-Price)。

#### R9：开仓和仓位大小

首仓和加仓只允许一条风险计算路径：

```text
单笔可用风险
= min(
    账户权益 × risk_per_trade,
    账户权益 × total_open_risk_limit - 当前总开放风险
  )

下单数量
= 单笔可用风险 / 每单位预期净亏损

所需保证金
= 下单数量 × 入场价 / 杠杆
```

随后再用单标的保证金上限、总保证金上限和可用余额缩小数量。杠杆只能降低保证金占用，不能增加允许亏损金额。

`A/S` 等级只负责排序和展示，初期不得让 S 级自动承担双倍风险。若后续数据证明 S 级有更高净期望，再单独提出风险分层 PRD。

模拟盘建议起始风险边界如下，全部复用现有配置，不增加新参数：

| 参数 | 当前值 | 建议模拟盘起点 |
|---|---:|---:|
| 单笔风险 | 1.0% | 0.5% |
| 组合开放风险 | 4.0% | 2.0% |
| 最大持仓数 | 5 | 3 |
| 总保证金占比 | 95% | 50% |
| 最大杠杆 | 10x | 5x |
| 日内亏损熔断 | 关闭 | 1.5% |
| 最大回撤熔断 | 关闭 | 8.0% |

这些数值是风险验证起点，不是收益最优值。正式调整必须和策略逻辑变更分批验证。

交易所下单前还必须按 `tickSize`、`stepSize` 和 `MIN_NOTIONAL` 归一化价格、数量和名义价值，不能先计算理论仓位后直接提交：[Binance USDⓈ-M 合约交易规则](https://developers.binance.com/zh-CN/docs/products/derivatives-trading-usds-futures/common-definition)。

#### R10：加仓和调仓

**第一阶段：关闭自动加仓。**

统一风险定仓和持仓元数据完成后，最多恢复一次加仓，且必须满足：

1. 禁止亏损加仓和摊低成本；
2. 原仓至少达到 `+1R`，止损已提高到保本或更优；
3. 出现新的同方向、同 setup 回踩确认；
4. 加仓后重算整仓均价、数量、止损、TP、净计划盈亏比；
5. 加仓后的整仓最坏亏损不得超过首仓原始风险预算；
6. 加仓与首仓共用同一个组合风险入口。

**自动轮动暂时关闭。**

不再因为候选标的 ATR、成交量或 OI 更高就主动平掉尚未失效的持仓。现有持仓按自己的退出规则结束，新候选等待空余仓位。这会减少换仓摩擦、滑点和高波动追涨杀跌。

#### R11：出场逻辑

持仓只保留四个可见阶段：

```text
OPEN → TP1_DONE → RUNNER → CLOSED
```

每根更新只允许执行一个最高优先级事件：

1. 交易所/账户紧急风险或硬止损；
2. setup 所属周期收盘确认结构失效；
3. TP1：平 35%，剩余仓位止损移到保本或更优；
4. TP2：普通行情平掉全部剩余仓位；
5. 单边行情到达 TP2 后，允许剩余 65% 转入移动保护；
6. TP1 前经过现有 `time_stop_bars=5` 且最大有利波动未达到 0.5R，退出无效率持仓。

出场约束：

- 新开仓的否决项不能自动触发旧持仓退出；
- 移动止损只能收紧，不能放宽；
- 加仓后必须按整仓口径重算已实现 R、未实现 R、MAE 和 MFE；
- `second_take_profit_fraction` 和 `trailing_remainder_fraction` 退役，剩余比例由 `1 - first_take_profit_fraction` 唯一计算；
- 条件同时命中时严格按上述优先级处理，避免同一根 K 线多次平仓。

### 2.4 改动范围

后续实施预计涉及：

- `src/ai_trading/strategy.py`：评分职责和 0～100 上限；
- `src/ai_trading/market_context.py`：保持现有状态模型，成为唯一行情状态权威；
- `src/ai_trading/paper.py`：标的池、主交易计划、入场门槛、加仓/轮动开关和退出优先级；
- `src/ai_trading/risk.py`：删除固定保证金绕过路径，统一风险定仓；
- `src/ai_trading/binance.py`：交易规则、价差和数据新鲜度；
- `src/ai_trading/models.py`：兼容字段和持仓阶段；
- `config/strategy.yaml`：合并/退役配置；
- 回测、模拟盘、API 和单元测试。

### 2.5 明确不在范围

- 不接真实资金账户，不修改真实订单；
- 不新增指标、机器学习、情绪数据或链上数据；
- 不增加盘口深度模型，除非价差和实盘滑点数据证明仅靠最优买卖价不足；
- 不开发币种专属参数；
- 不承诺提高固定百分比的胜率；
- 不一次性重写 `paper.py`；
- 不在评分职责尚未稳定时同步优化所有阈值。

## 3. 技术方案

### 3.1 目标决策链

```text
UniverseEligible
  ├─ 合约状态/成交额
  ├─ 流动性/价差
  └─ 数据完整、新鲜
        ↓
MarketContext
  ├─ 4H方向
  ├─ 拥挤
  ├─ 流动性
  └─ 系统风险
        ↓
SetupScore（闭合K线内固定）
        ↓
PrimaryTradePlan
  ├─ 一个主入场区
  ├─ 一个结构失效位
  └─ 真实目标与净计划R
        ↓
EntryGate（逐项通过）
        ↓
PortfolioRiskGate（唯一仓位入口）
        ↓
OPEN → TP1_DONE → RUNNER → CLOSED
```

### 3.2 与当前逻辑的对比

| 方面 | 当前逻辑 | 本次建议 | 解决的问题 |
|---|---|---|---|
| 评分 | 基础分、多周期分、入场质量分共同形成最终分 | 只有闭合 K 线 `setup_score`；价格质量只做门槛 | 分数稳定、可比较、可回测 |
| EMA/VWAP/BOLL/KC | 既参与方向和分数，又形成多个入场区并可能再次影响分数 | 保留方向/评分作用；入场只复用为合并区域，不二次加分 | 不丢失有效信息，也不重复奖励 |
| 标的池 | Top20 配置与 Top80/Top50 运行口径并存 | 成交额降序 Top80 后严格筛选 `setup_score > 65` | 行为可解释，并避免评分改变成交额池顺序 |
| 行情状态 | 新旧多个状态字段共同决策 | `market_context` 唯一决策源，旧字段只兼容输出 | 避免同一行情被不同模块解释成不同状态 |
| 入场区 | 多个区任一命中即可 | 一个 setup 对应一个主区 | 降低“总能找到一个理由入场”的概率 |
| 优秀入场 | 好价格和高 RR 增加最终分 | 好价格、触发、RR 都是必须通过的门槛 | 高分不再掩盖追价或低盈亏比 |
| 止盈 | 结构不足时可生成更远 runner | 只承认真实目标，未知 runner 不计入开仓前收益 | 防止人为抬高盈亏比 |
| 开仓 | 固定保证金与风险定仓两条路径 | 所有订单先按最大亏损定仓 | 杠杆、等级和加仓不能突破风险上限 |
| 加仓 | 固定资金单位，均价后风险口径不完全统一 | 首期关闭；恢复后整仓风险不得超过原始 1R | 防止“首仓安全、加仓后失控” |
| 轮动 | 依据波动、量和 OI 替换持仓 | 暂停主动轮动 | 减少手续费、滑点和高波动追价 |
| 出场 | 多条件分支，执行顺序形成隐含优先级 | 四阶段、固定优先级、每次一个事件 | 出场可测试、可复盘 |

### 3.3 为什么更好

1. **提高准确性**：一个 setup 只有一个方向、一个主区和一个失效位，减少模糊匹配。
2. **提高分数可信度**：分数不再随实时价格变化，排名、复盘和回测口径一致。
3. **提高胜率的合理路径**：通过等待优势价格、确认触发和真实结构目标，减少追价与低质量入场；不是通过缩小止盈来制造表面胜率。
4. **规避大亏风险**：所有订单按止损风险定仓，避免固定保证金、杠杆或加仓绕过账户风险预算。
5. **减少过拟合**：不增加指标、不增加币种参数，删除重复职责和未生效配置。
6. **降低维护成本**：各模块只回答一个问题，失败原因能够直接定位。

### 3.4 数据和判定时点

- 方向、setup、结构和触发只使用已收盘 K 线；
- 实时价格只用于判断是否进入主区、计算可成交净 R 和下单数量；
- 流动性和系统风险允许使用实时快照，但必须带时间戳和新鲜度；
- 同一个 `setup_id` 在有效期内不得回写历史分数；
- 回测标的池必须使用当时可获得的数据，不能用今天的 Top80 回测过去。

## 4. 兼容性问题

### 4.1 API 兼容

兼容期保留现有字段：

- `score`：暂时映射为 `setup_score`；
- `entry_quality_score`：固定为 0，并标记废弃；
- `entry_levels`：继续输出，但只把 `primary` 作为可执行区，其余仅展示；
- `regime`、`trend_state`、`risk_state`：由 `market_context` 映射生成，不再独立计算；
- `action`、`vetoes`、`suggested_entry` 保持字段名不变。

增加字段时优先复用现有 payload，不立刻改成复杂嵌套对象。待前端、历史记录和测试全部迁移后，再删除废弃字段。

### 4.2 配置兼容

建议映射：

- `symbols_mode` 成为唯一池大小来源；
- `score_threshold` 暂时继续作为 setup 候选阈值；
- `watch_threshold` 暂时保持；
- `first_take_profit_fraction` 保留；
- `second_take_profit_fraction`、`trailing_remainder_fraction` 标记废弃；
- `requested_margin_usdt` 只允许作为风险定仓后的上限，不得成为独立定仓路径；
- 未被生产路径读取的配置先记录告警，经过一个兼容版本后删除。

配置加载要对旧 YAML 保持容忍；废弃字段存在时不能导致启动失败。

### 4.3 持仓兼容

升级时已有模拟持仓必须继续按原计划管理，禁止悄悄重算止损和 TP：

1. 新持仓写入 `plan_version`；
2. 老持仓缺少版本时按 legacy exit 管理；
3. 新逻辑只管理升级后新开的持仓；
4. 加仓功能关闭时，不影响旧仓正常减仓和退出；
5. 所有迁移先在模拟盘执行。

### 4.4 回测兼容

- 保留当前策略版本作为基线；
- 新旧版本使用相同 K 线、资金费、手续费、滑点和标的池快照；
- 同根 K 线同时碰到止损和止盈时采用保守成交顺序；
- 不能用未来 1H/4H 收盘信息决定当前 15m 入场；
- 不能因为新版本交易更少，就只比较胜率。

## 5. 风险点

| 风险 | 表现 | 缓解措施 |
|---|---|---|
| 交易次数明显下降 | 单主区、真实目标和净 R 门槛会过滤更多信号 | 以净期望和回撤评估，不以交易数量验收 |
| 1.30R 门槛不适配所有阶段 | 趋势和震荡的最佳 R 可能不同 | 初期只设一个阈值；走步验证后再决定是否需要状态差异 |
| 状态迁移改变历史行为 | 新旧状态映射不完全一致 | 先影子运行，记录差异，不直接切换真实执行 |
| Top80 中合格标的数量波动 | `setup_score > 65` 后主池可能明显少于 80 | `UNKNOWN` 流动性/系统风险状态在启动期不硬拦截；只让明确 `THIN`/`STRESS` 状态否决新开仓 |
| 真实目标限制错过大趋势 | 没有结构目标时系统会等待 | runner 可用于持仓管理，但不计入开仓前盈亏比 |
| 关闭加仓和轮动降低趋势收益 | 强趋势中资本利用率下降 | 先证明首仓风险链正确，再恢复一次受控加仓 |
| 低风险参数降低收益 | 0.5% 单笔风险和 50% 保证金限制更保守 | 以单位风险收益评估，验证后逐步调整，不一次放大 |
| 旧字段兼容期形成双逻辑 | 输出相同、内部读取可能未完全迁移 | 对每个决策字段增加来源审计，禁止旧字段直接参与新开仓 |
| 过度追求胜率 | 通过小止盈得到高胜率但净期望下降 | 验收主指标使用净 R、Profit Factor、回撤和尾部损失 |

## 6. 改动计划

本 PRD 只定义计划，不授权施工。

### 阶段 0：基线冻结

- 固定当前版本、配置和历史样本；
- 导出当前每笔信号的分数、入场理由、否决、止损、TP、仓位和退出原因；
- 建立旧版本可重复回测基线；
- 记录所有配置的实际读取位置，确认死配置。

验收：同一数据集重复运行结果一致，旧版本可随时回滚。

### 阶段 1：先修正确性

- 将 `entry_quality_score` 从最终分移除；
- 固定 `setup_score`；
- 统一 `PortfolioRiskGate`，取消固定保证金提前返回；
- 无真实目标或净 R 不足时禁止自动开仓；
- 停止自动加仓和主动轮动。

验收：

- 同一根已收盘 K 线内实时价格变化不改变 `setup_score`；
- 任意下单路径都不能突破单笔风险和总开放风险；
- 目标缺失时零自动开仓；
- 不再生成用于开仓放行的理论 TP2。

### 阶段 2：收敛核心决策

- 标的池统一为一个配置口径；
- `market_context` 成为唯一内部行情状态源；
- 每个 setup 只输出一个主入场区；
- 支撑压力按三类价位和固定优先级收敛；
- 入场门槛统一输出可机器识别的失败原因。

验收：

- 一个候选方向最多一个可执行主区；
- 同一时点所有模块读取相同的方向、流动性和系统风险状态；
- 任一入场失败能够落到唯一原因码。

### 阶段 3：退出和兼容迁移

- 建立四阶段持仓管理；
- 实现 TP1 35%、剩余 65% 的清晰语义；
- 让 `time_stop_bars` 进入主退出链；
- 新老持仓按 `plan_version` 隔离；
- 废弃但暂不删除旧 API 和配置字段。

验收：

- 同一次价格更新最多产生一个退出事件；
- 止损只收紧不放宽；
- TP、时间退出和结构失效顺序可由测试证明；
- 老持仓行为不被新版本静默改变。

### 阶段 4：验证后决定是否上线

验证顺序：

1. 单元测试和属性测试；
2. 无未来数据的事件回放；
3. 走步样本外回测；
4. 模拟盘至少覆盖趋势、震荡和系统风险三类市场；
5. 小规模灰度；
6. 达标后才讨论恢复一次加仓。

核心指标：

- 扣费后每笔净期望 R；
- Profit Factor；
- 最大回撤和恢复时间；
- 胜率及其置信区间；
- 95%/99% 尾部单笔亏损；
- 计划风险与实际亏损偏差；
- 平均滑点、换手率和资金费；
- 各否决原因拦截后的结果分布；
- setup 分数分桶后的样本外胜率与净期望。

最低上线条件：

- 风险上限违规次数为 0；
- 同根闭合 K 线分数稳定率为 100%；
- 样本外净期望不低于基线；
- 最大回撤不恶化；
- 计划亏损与实际亏损的 P95 偏差不超过 10%；
- 至少积累 200 笔样本外交易；不足则延长样本，不降低标准。

## 8. 最终验收定义

本次优化完成的标准不是“代码增加了多少”，而是以下问题都只有一个清晰答案：

1. **为什么这个标的进入池？**  
   因为合约状态、成交额、实时流动性和数据完整性全部合格。

2. **为什么选择这个方向？**  
   因为唯一行情上下文和固定机会评分支持该方向。

3. **为什么现在开仓？**  
   因为价格进入唯一主区优势侧、触发确认、无否决、真实目标存在且净计划 R 达标。

4. **如果判断错误，最多亏多少？**  
   因为所有路径由唯一组合风险入口按结构止损距离计算仓位。

5. **为什么退出？**  
   因为该笔交易触发了固定优先级中的一个明确事件，而不是另一套新开仓信号改变了旧持仓。

当这五个问题能在每笔交易复盘中得到唯一、可重现的答案，系统才算真正“更简单、更准确、更可控”。
