# AI Trading 合约策略 VNext PRD

> 文档状态：Draft / 仅需求评审  
> 版本：v0.1  
> 日期：2026-07-28  
> 适用范围：Binance USDT-M 永续合约、研究与模拟交易  
> 本阶段约束：只定义需求、验收标准与实施顺序，不修改策略代码，不接入实盘

## 1. 背景与结论

当前系统已经具备一条较完整的策略链路：

`Top50 候选池 → 1D/4H/1H/15m 行情结构 → 多空评分 → 入场区 → 触发与否决 → 结构止损/止盈 → 固定资金单元开仓 → 加仓/轮动 → 多条件退出`

工程层面的优点包括：

- 实时模拟与历史回放共用 `PaperTradingEngine`，避免出现两套完全不同的交易状态机。
- 正向证据已按均线位置、衍生品、方向、触发、入场质量进行部分去重。
- 已有 1D/4H/1H/15m 多周期上下文、OI、资金费率、主动买卖、大户持仓、ATR、VWAP、BOLL、Keltner 等信息。
- 自动开仓要求存在入场区、触发、结构止损，并对止损/止盈方向做了后置断言。
- 已有 279 个自动化测试通过，说明当前行为有较好的回归保护。

但从“可持续迭代的合约交易系统”角度，当前最大问题不是指标不够，而是：

1. **评分、入场质量、否决、风险预算仍有交叉与语义冲突。**
2. **自动开仓使用固定保证金单元时，没有执行组合总风险和单标的风险上限。**
3. **实际结构盈亏比不足或不可计算时，部分场景仍可继续开仓。**
4. **95% 保证金部署、5–10 倍杠杆与默认关闭的账户熔断组合过于激进。**
5. **标的池筛选只覆盖成交额和硬编码排除名单，已有 `UniverseSelector` 没进入生产链路。**
6. **止盈、时间止损、减仓比例等配置与真实持仓状态机不一致。**
7. **加仓和轮动没有按加仓后的总风险、净期望收益和相关性统一决策。**
8. **历史回放存在当前 Top50 幸存者偏差，且 15m OHLC 内路径只能近似成交过程。**

因此，本 PRD 的方向是：**减少隐式分支与硬编码，建立可解释、可校准、风险先行的单一决策管线。**

## 4. 产品目标

### 4.1 核心目标

1. 建立一条唯一、可审计的自动交易决策管线。
2. 将“策略得分”“入场计划质量”“硬否决”“组合风险”彻底分层。
3. 每一笔开仓必须能回答：
   - 为什么是这个标的和方向？
   - 为什么是这个区间和当前价格？
   - 哪个价格证明判断错误？
   - 扣除费用、资金费率和滑点后的目标空间是多少？
   - 最坏情况下账户损失多少？
   - 与现有仓位的相关风险是多少？
4. 加仓后账户风险不得超过加仓前批准的风险预算。
5. 出场状态机必须确定性、幂等、可回放。
6. 所有阈值必须可配置、可版本化、可做 walk-forward 验证。

### 4.2 非目标

- 本阶段不接入真实下单 API。
- 不承诺稳定盈利、固定胜率或固定收益。
- 不以增加更多指标为主要成果。
- 不引入无法解释的黑盒模型直接控制仓位。
- 不为了提高回测收益而放宽数据完整性或成交保守性。
- 不同时维护“实时一套、回测一套”的策略判断。

## 5. VNext 决策管线

```mermaid
flowchart LR
    A["交易所可交易合约"] --> B["标的池与数据质量"]
    B --> C["市场状态向量"]
    C --> D["多空 Setup 检测"]
    D --> E["基础策略评分"]
    E --> F["结构化入场计划"]
    F --> G["硬否决与执行校验"]
    G --> H["组合风险与仓位计算"]
    H --> I["模拟成交与保护单"]
    I --> J["持仓状态机"]
    J --> K["退出、归因与再入场屏障"]
```

唯一自动开仓条件定义为：

```text
ENTRY_READY =
    universe_eligible
    AND data_quality_pass
    AND higher_timeframe_direction_pass
    AND setup_score_pass
    AND primary_entry_zone_hit
    AND trigger_confirmed
    AND hard_veto_count == 0
    AND net_rr_pass
    AND portfolio_risk_pass
    AND execution_constraints_pass
```

任何一项失败都必须返回稳定的机器码和人类可读原因，不得依赖解析自然语言字符串控制交易。

## 6. 功能需求

### FR-01 标的池筛选

#### 需求

1. 将标的池拆为三层：
   - `ExchangeUniverse`：交易状态正常的 USDT-M 永续合约。
   - `EligibleUniverse`：通过流动性、交易规则、数据质量、上市时长的合约。
   - `RankedCandidatePool`：按机会质量排序、供策略扫描的候选池。
2. 不再硬编码排除 BTC、ETH、SOL。改为可配置的 `asset_tier`：
   - `MAJOR`
   - `LARGE_ALT`
   - `MID_ALT`
   - `HIGH_RISK`
3. 最低准入条件至少包含：
   - 24h quote volume 分位数和绝对下限。
   - bid/ask spread bps。
   - 距中间价 10/25 bps 内的盘口深度。
   - 最低上市天数。
   - 1h/4h K 线连续性。
   - OI、资金费率、long/short ratio 覆盖率与延迟。
   - 合约状态、tick size、step size、min notional。
4. 将现有 `UniverseSelector` 合并进生产路径，不保留旁路实现。
5. 候选池排序不得只使用策略分数，至少拆为：
   - `liquidity_score`
   - `data_quality_score`
   - `opportunity_score`
   - `portfolio_fit_score`
6. 引入 BTC/ETH 相关性分组或聚类，限制同方向高度相关仓位集中。
7. 历史回放必须支持 point-in-time universe；若数据无法获得，报告必须将该次结果标记为“不可用于策略晋级”，而不只是文字提示。

#### 验收

- 配置中的池大小与运行时完全一致。
- 每个被排除标的都有固定 `reason_code`。
- 不满足交易所价格、数量、最小名义价值过滤器的计划无法进入开仓。
- 任一时间点只使用当时可见的标的和数据。
- 主流币是否参与由配置决定，不再需要修改源码。

### FR-02 行情判断

#### 需求

用状态向量替代单一 `regime` 承载所有语义：

```text
MarketState:
  trend: UP / DOWN / RANGE / TRANSITION
  trend_strength: 0..100
  volatility: LOW / NORMAL / HIGH / EXTREME
  liquidity: GOOD / THIN / DISLOCATED
  crowding: LONG_CROWDED / BALANCED / SHORT_CROWDED
  derivatives_flow: BUILD / UNWIND / ABSORPTION / CONFLICT
  systemic_risk: NORMAL / BTC_SHOCK / DATA_DEGRADED
```

具体要求：

1. 1D 只做背景，4H 决定方向门，1H 定义 setup 和触发，15m 只优化执行，不得单独反转 4H 方向。
2. 趋势强度使用多个可解释维度：均线斜率、价格效率、结构高低点、ATR/BOLL 宽度分位数。
3. 波动阈值使用滚动分位数或按资产层级归一化，避免所有币共用绝对阈值。
4. 状态切换加入滞回和最短持续时间，防止一根 K 线反复切换趋势/震荡。
5. BTC 系统性风险不只看 4H 振幅，还应考虑：
   - 短周期 realized volatility。
   - mark/index basis 异常。
   - 全市场 spread 扩张。
   - 资金费率和 OI 冲击。
   - 数据源降级。

#### 验收

- 相同输入产生完全相同状态。
- 状态变化有原因、源时间戳和版本号。
- 15m 数据不能越权创建与 4H 相反的自动方向。
- 状态滞回规则具有单元测试和回放测试。

### FR-03 策略评分

#### 需求

1. 将最终分数约束到 `0..100`，不再用 `100+` 表示 S。
2. 评分拆为互不越权的五个部分：

| 子分数 | 建议权重 | 说明 |
|---|---:|---|
| Direction | 25 | 4H 方向、1D 背景，不含入场位置 |
| Setup | 25 | 突破回踩、趋势回调、派发、OI valley 等结构质量 |
| Trigger | 20 | 1H/15m 收盘确认、成交量、主动成交 |
| Derivatives | 15 | OI、主动买卖、大户持仓、拥挤状态 |
| Data/Execution Quality | 15 | 数据质量、流动性、费用和可执行性 |

3. 真实盈亏比不再给基础策略“加分并抬过门槛”。它属于独立的 `EntryPlanQuality` 门。
4. 同源证据只能贡献一次：
   - EMA/BOLL/VWAP/Keltner 位置归入同一位置族。
   - OI、主动买卖、大户持仓归入衍生品流族。
   - 1D/4H 归入方向族。
   - 1H/15m 归入触发族。
5. 多头和空头独立评分；同分不默认多头。分差不足时进入 `DIRECTION_CONFLICT`。
6. 每个 setup 独立统计分数分桶的：
   - 胜率。
   - 平均 R。
   - 净期望 R。
   - 最大不利波动 MAE。
   - 最大有利波动 MFE。
7. 阈值通过 walk-forward 和样本外结果校准。没有足够样本的 setup 标记为 `UNVALIDATED`，不得自动使用 S 级仓位。

#### 验收

- 分数始终在 0–100。
- 每一分都能追踪到 `evidence_code`、原始值、标准化值和贡献分。
- 同一证据族不得重复累计。
- 分数高低分桶的样本外净期望总体呈单调关系；若不单调，不能用于仓位分级。
- 评分阈值、模型版本和参数快照随交易记录持久化。

### FR-04 支撑位和压力位

#### 需求

建立统一 `StructuralLevel`：

```text
StructuralLevel:
  id
  side: SUPPORT / RESISTANCE
  timeframe
  zone_low
  zone_high
  source: SWING / RANGE / BREAK_RETEST / EMA_CLUSTER / VWAP / VOLUME_NODE
  touch_count
  rejection_count
  breakout_state
  volume_confirmation
  oi_confirmation
  strength_score
  created_at
  last_tested_at
  expires_at
```

1. 水平支撑压力优先使用确认摆动点和突破/回踩，不只使用最近 20 根的极值。
2. 区间宽度由 ATR、spread 和 tick size 共同决定。
3. 每个 level 有强度分：
   - 周期越高权重越大。
   - 触碰和收盘拒绝增加强度。
   - 放量突破后角色转换。
   - 反复穿越、时间过久、OI/成交不确认会衰减。
4. 同一价格附近的多个 level 合并为 confluence zone，不能在界面和策略里作为多个独立证据重复加分。
5. 止损和目标必须引用具体 `level_id`，便于退出归因。

#### 验收

- 每个建议入场区、止损和结构目标都有可追踪的 level。
- 已失效 level 不再参与评分或开仓。
- 同一区域合并后不会重复加分。
- 4H level 不会被 15m 噪声任意覆盖。

### FR-05 建议入场位置与“优秀入场”

#### 需求

每个候选信号生成一个唯一 `EntryPlan`：

```text
EntryPlan:
  setup_id
  side
  direction_timeframe
  entry_timeframe
  primary_zone
  trigger
  invalidation_level
  hard_stop
  targets
  order_type
  max_chase_bps
  expires_at
  net_rr
  expected_cost
  status
```

1. 只能选择一个 `primary_zone`，其他区间仅作为 confluence。
2. `primary_zone` 由 setup 决定，不允许运行时因为某个通用 EMA 更近而替换 setup 的核心位置。
3. `EXCELLENT_ENTRY` 必须同时满足：
   - 4H 方向建立。
   - setup 基础评分达标。
   - 当前可执行价格进入 primary zone 的优势部分。
   - 1H 收盘触发已确认；15m 只能提高执行精度。
   - 没有硬否决。
   - 扣除双边手续费、滑点、预计资金费率后的净盈亏比达标。
   - 止损距离、强平距离、盘口深度和组合风险达标。
4. 建议研究起始门槛：
   - A：净 RR ≥ 1.5。
   - S：净 RR ≥ 2.0，且基础策略分数、数据质量和流动性均达到 S。
   - 任何例外必须是 setup 级版本化参数，并经过样本外验证。
5. 当结构目标空间不足时返回 `WAIT_FOR_BETTER_PRICE`，不得自动生成穿越最近强压力/支撑的理论 TP2 来凑 RR。
6. EntryPlan 必须有 TTL；方向、结构、价格离开区间或数据过期时自动失效。
7. 区分：
   - `LIMIT_AT_ZONE`
   - `MARKET_ON_CONFIRMATION`
   - `STOP_ON_BREAKOUT`
   并定义最大追价 bps。

#### 验收

- 每次开仓只有一个 primary setup、一个 primary zone、一个失效点。
- `net_rr` 不可计算、低于门槛或数据过期时绝不自动开仓。
- “进入建议区”与“触发确认”是两个独立状态。
- 价格离开允许追价范围后，旧信号不能市价追单。

### FR-06 否决体系

#### 需求

用结构化对象替代字符串驱动：

```text
Veto:
  code
  severity: HARD / SOFT
  scope: SYMBOL / SIDE / PORTFOLIO / SYSTEM
  source_timeframe
  observed_value
  threshold
  created_at
  expires_at
  message
```

硬否决至少分为：

1. `DATA_*`：数据缺失、过期、不连续、时间错位。
2. `DIRECTION_*`：4H 反向、趋势线突破未回踩、方向冲突。
3. `ENTRY_*`：不在 primary zone、触发未确认、追价、结构 RR 不足。
4. `MARKET_*`：极端波动、流动性失常、mark/index basis 异常。
5. `DERIVATIVES_*`：与 setup 冲突的 OI/主动成交/大户持仓。
6. `PORTFOLIO_*`：风险、回撤、日/周损失、相关性、仓位数。
7. `EXECUTION_*`：tick/step/min notional、深度不足、保护单无法建立。

原则：

- **硬否决不允许通过高分抵消。**
- 软风险只影响分数或仓位系数，不同时又作为硬否决。
- 每个否决必须有明确失效条件。
- 新开仓否决与持仓退出条件分离；“不适合新开仓”不等于“立即平掉已有仓位”。

#### 验收

- 自动开仓只检查机器码和严重级别，不解析 message。
- 同一个风险在全链路只有一个定义。
- 界面能显示否决来源、当前值、阈值和何时重新评估。
- README、API 和实际执行对硬否决的定义一致。

### FR-07 开仓与组合风险

#### 需求

1. 仓位大小统一按止损风险计算：

```text
risk_budget =
    equity
    × base_risk_pct
    × setup_factor
    × drawdown_factor
    × liquidity_factor
    × correlation_factor

quantity = risk_budget / abs(entry_fill - stop_fill_assumption)
```

2. 保证金是风险计算后的结果，不能作为绕过风险预算的另一条生产路径。
3. 无论手动指定保证金、A/S 资金单元或加仓，都必须同时检查：
   - 单笔风险。
   - 单标的总风险。
   - 组合 open risk。
   - 同相关性分组风险。
   - 总保证金。
   - 可用余额。
4. 研究阶段建议安全起始值：

| 项目 | 建议初始值 |
|---|---:|
| A 单笔风险 | 0.50% equity |
| S 单笔风险 | 0.75% equity |
| 单标的含加仓最大风险 | 1.00% equity |
| 组合总 open risk | 2.00% equity |
| 同相关性分组风险 | 1.00% equity |
| 日损失熔断 | 2.00% |
| 周损失熔断 | 4.00% |
| 账户最大回撤熔断 | 8.00% |
| 总保证金建议上限 | 50% equity |

以上是模拟研究基线，不是收益保证；最终值必须通过压力测试确定。

5. 杠杆只影响保证金效率，不改变允许损失：
   - 先确定止损和风险预算，再求数量和最低必要杠杆。
   - 必须估算强平价。
   - `distance(entry, liquidation)` 必须显著大于 `distance(entry, hard_stop)`，并保留费用和跳空缓冲。
6. 每笔自动开仓必须先建立保护计划；若保护单不可建立则 fail closed。
7. `paper_trading` 配置必须真正控制执行模式，不能只作为展示字段。

#### 验收

- 任意入口都无法超过组合、单标的和相关性风险上限。
- 95% 固定部署不再是默认生产策略。
- 风险面板展示值与风险门实际判断一致。
- 加仓、滑点或部分成交后会重算真实 open risk。
- 强平价、止损价、预计最坏损失均写入交易记录。

### FR-08 止盈止损

#### 需求

1. 止损分为：
   - `hard_stop`：交易所级/模拟强制保护，不等待 K 线收盘。
   - `soft_invalidation`：结构收盘失效，可触发主动退出。
2. hard stop 必须来自：
   - primary structure 外侧。
   - ATR 噪声缓冲。
   - spread、tick size 和预估滑点。
3. 开仓后 hard stop 只能向盈利方向移动，不得放宽。
4. 目标优先级：
   - 最近有效结构目标。
   - setup 的测量目标。
   - runner 的动态 trailing。
5. 建议默认分批：
   - TP1：30%–35%，达到约 1R 或第一个有效结构。
   - TP2：30%–40%，达到第二结构目标。
   - Runner：剩余部分，按趋势结构追踪。
   三者之和必须等于 100%。
6. TP1 后的保本价必须覆盖开仓费、平仓费、滑点和已发生资金费率。
7. 时间止损接入生产状态机：
   - 按 setup 和 entry timeframe 计算已持有的已收盘 K 线数量。
   - 在限定时间内未达到最低 MFE 或方向未验证，减仓或退出。
8. 发生跳空越过 stop 时，按可成交价格和保守滑点退出，不能按 stop 理论价计算。

#### 验收

- `first_take_profit_fraction`、`second_take_profit_fraction`、`runner_fraction` 均真实生效且合计 1。
- `bars_held` 随对应周期收盘递增。
- 每次止损和目标调整保留历史记录。
- 结构空间不足不会通过虚构更远目标绕过开仓门。

### FR-09 加仓逻辑

#### 需求

1. 禁止亏损加仓和摊低成本。
2. 只有满足以下条件才允许加仓：
   - 首仓已经验证，建议至少达到 1R 或 TP1 完成。
   - 首仓 stop 已移到覆盖全部成本的无风险区。
   - 出现新的、独立的 pullback/retest setup 和新触发。
   - 新增后单标的总风险和组合风险仍达标。
   - 加仓价格仍有合格净 RR。
3. 加仓后必须重算：
   - 加权平均成交价。
   - 总数量。
   - 统一 hard stop。
   - 总 open risk。
   - 新 TP1/TP2/runner 数量。
   - MAE/MFE 和 R 的基准。
4. `margin_factor` 等风险缩放字段必须真实影响风险预算；若不使用则删除，不能只显示。
5. 加仓次数不是唯一约束，核心约束是“新增后风险不得扩大到预算之外”。

#### 验收

- 加仓后最坏损失不高于批准后的单标的风险上限。
- 不存在旧 `initial_stop_distance` 继续支配新组合仓位 R 的情况。
- 加仓成交滑点后再次校验风险；不满足则缩量或取消。

### FR-10 调仓/轮动逻辑

#### 需求

1. 轮动不是简单比较分数或 ATR/量能，统一比较：

```text
rotation_utility =
    candidate_expected_value
    - incumbent_expected_value
    - close_cost
    - open_cost
    - funding_cost
    - correlation_penalty
    - churn_penalty
```

2. 只有 `rotation_utility` 超过配置门槛才执行。
3. 候选标的必须完整通过 EntryPlan、无否决和组合风险门。
4. 不轮动：
   - 已进入盈利保护阶段且趋势仍有效的仓位。
   - 刚开仓未完成最小观察期的仓位。
   - 仅因候选波动更大、但净期望没有明显提升的场景。
5. 轮动后设置双向冷却和再入场屏障，防止来回换仓。

#### 验收

- 每次轮动记录 incumbent EV、candidate EV、全部成本和净提升。
- 候选分数低于当前仓位且没有更高净 EV 时不得轮动。
- 费用和滑点加倍压力下，轮动逻辑不能成为主要亏损来源。

### FR-11 出场逻辑

#### 需求

建立显式持仓状态机：

```text
OPENED
  → VALIDATING
  → VALIDATED
  → TP1_DONE
  → TP2_DONE
  → RUNNER
  → EXITING
  → CLOSED
```

退出优先级固定为：

1. 系统/强平应急。
2. hard stop。
3. 数据安全和账户 kill switch。
4. setup 结构失效。
5. TP1 / TP2。
6. 利润保护和 trailing。
7. 时间止损。
8. 轮动。
9. 手动退出。

其他要求：

- 每个事件只允许一个状态转换和一个主退出原因。
- 指标型退出使用与 setup 一致的周期；4H setup 不被 15m/1H 普通噪声直接关闭。
- 新开仓风险提示不能自动复用为平仓理由。
- 退出原因同时保留：
  - `exit_code`
  - `exit_category`
  - `trigger_value`
  - `reference_level_id`
  - `realized_r`
  - `fees`
  - `funding`
  - `slippage`

#### 验收

- 同一价格事件不会重复平仓。
- 状态机在实时模拟和历史回放结果一致。
- 所有完整交易均能归因到唯一主退出类别。
- TP2、runner、time stop 不再是未使用配置或死状态。

### FR-12 模拟成交与交易所约束

#### 需求

1. 模拟交易必须真实应用配置中的手续费和滑点，而不只用于显示 RR。
2. 滑点模型至少考虑：
   - spread。
   - 下单名义价值相对盘口深度。
   - 波动状态。
   - 市价/限价/stop 单类型。
3. 支持部分成交、未成交、价格跳过和订单 TTL。
4. 使用 mark price 评估强平和条件单触发语义，成交使用可成交 bid/ask 或保守模型。
5. 执行前应用 Binance 合约过滤器：`PRICE_FILTER`、`LOT_SIZE`、`MARKET_LOT_SIZE`、`MIN_NOTIONAL`、价格振幅限制等。Binance 官方文档明确这些规则会约束价格、止损价、数量和最小名义价值，不能等到实盘接入时再补。
6. 所有数量和价格按交易所精度向不利方向舍入后，重新校验 RR 和风险。

#### 验收

- 模拟账户实际 PnL 已扣除手续费、资金费率和成交滑点。
- 任一不满足交易所过滤器的订单在模拟阶段即被拒绝。
- 部分成交后仓位、风险和保护单数量一致。
- 行情流中断或延迟时禁止新开仓，已有仓位仍有安全价格回退与告警。

## 7. 历史回放与策略验证

### 7.1 必须修正的偏差

1. **幸存者偏差**：使用历史时点可交易合约、历史成交额排名和退市币。
2. **前视偏差**：只允许使用当时已收盘数据；衍生品数据按实际发布时间对齐。
3. **K 线内路径偏差**：
   - 优先使用 1m 或更细数据驱动 15m setup 的成交与止损。
   - 只有 OHLC 时使用明确的保守路径，并将结果标为估算。
4. **成交偏差**：引入 bid/ask、滑点、部分成交、tick/step/min notional。
5. **资金费率偏差**：按真实结算时间和持仓名义价值计费。
6. **参数偏差**：参数选择只使用训练窗口，验证窗口完全隔离。

### 7.2 Walk-forward 方案

建议最少覆盖：

- 牛市、熊市、震荡、高波动和低流动性阶段。
- 12 个月以上可用历史；受衍生品接口限制时，以自建增量数据仓补足。
- 按月或季度滚动训练/校准，下一个窗口只验证不调参。
- 每个 setup、方向、资产层级和市场状态分别报告。

### 7.3 必备指标

- 净收益、净期望 R、Profit Factor。
- 胜率、平均盈亏比、平均持有时长。
- 最大回撤、回撤持续时间。
- MAE/MFE。
- 手续费、滑点、资金费率占毛利润比例。
- 每个 score bucket 的净期望与置信区间。
- 每个 setup、regime、资产层级的贡献。
- 单标的和相关性分组的风险集中度。
- 否决原因分布、错失后最大有利波动。
- 轮动前后净效用。

## 8. 策略晋级门槛

以下门槛用于“允许进入长期 shadow/paper 验证”，不等于允许实盘：

### 8.1 正确性门槛

- 组合风险、单标的风险、相关性风险违规次数为 0。
- 无前视数据、无未收盘 K 线越权。
- 每个开仓都有完整 EntryPlan、hard stop、目标、净 RR、风险金额和版本号。
- 所有配置项必须满足“真实生效”或“删除”，不得存在展示型死配置。
- 实时模拟与历史回放对同一事件序列产生相同状态转换。

### 8.2 统计门槛

- 样本外净期望大于 0R。
- 样本外 Profit Factor 大于 1，并优于当前基线；建议晋级线为 1.15，但需结合样本量。
- 费用与滑点加倍压力下不出现不可接受的负期望。
- 高分桶的样本外净期望不低于相邻低分桶；否则取消 A/S 仓位分级。
- 至少 200 笔样本外完整交易；单 setup 少于 50 笔时标记 `INSUFFICIENT_SAMPLE`。
- 收益不得过度依赖单一标的、单一月份或单一 setup。
- 最大回撤不超过预先批准的风险预算，且不得用提高杠杆掩盖。

### 8.3 Shadow/Paper 门槛

- 连续运行至少 8 周无状态错误、重复平仓、丢失保护计划或账户不一致。
- 模拟成交与实际可观察盘口偏差可解释。
- 数据中断、API 限流、WebSocket 重连和进程恢复均有演练记录。
- 达到门槛后仍需单独编写实盘执行 PRD，本 PRD 不授权实盘。

## 9. 配置治理

- `paper_trading` 必须实际参与执行门。
- `qps_min_ratio` 要么接入，要么删除。
- `vwap_*` 和 `volume_breakout/pullback/restart_*` 必须进入 YAML 并有范围校验。

- `time_stop_bars` 接入并真实递增 `bars_held`。
- `margin_factor` 接入风险预算，不再只写信号。
- README 中硬否决描述与实际 `Veto` 规则统一。

### 9.2 配置要求

- 使用 schema 验证范围、枚举和比例之和。
- 启动时拒绝未知字段、失效字段和危险组合。
- 每次交易保存完整配置 hash 与策略版本。

## 10. 可观测性与界面

每个候选标的必须展示：

1. 标的池排名与准入质量。
2. 市场状态向量。
3. 多空基础分、证据族和分差。
4. primary setup、primary zone、触发状态。
5. 建议入场价、允许追价、失效时间。
6. hard stop、soft invalidation、TP1、TP2、runner。
7. 扣费前/后的 RR。
8. hard veto 与 soft risk。
9. 计划风险金额、组合 open risk、相关性风险。
10. `WAIT` 时下一步需要发生什么。

每个持仓必须展示：

- 当前状态机阶段。
- 初始风险 R 与当前锁定 R。
- MAE/MFE。
- 下一状态转换条件。
- 加仓后综合成本和综合风险。
- 退出优先级中当前最接近触发的条件。

## 11. 实施优先级

### P0：风险正确性与行为一致性

1. 统一 RiskGate，修复固定保证金和加仓绕过 open-risk/symbol-risk。
2. 净 RR 不足或不可计算时一律禁止自动开仓。
3. 降低默认资金部署，启用账户级损失与回撤保护。
4. 接入 `margin_factor`、时间止损、第二止盈和 runner；或删除死配置。
5. 实时模拟实际应用手续费、滑点和交易所过滤器。
6. 建立结构化 Veto 和稳定 reason code。

### P1：选币、行情、评分与入场计划

1. 统一 UniverseSelector 与 TopN 配置。
2. 增加流动性、点差、深度、数据完整性和相关性筛选。
3. 建立 MarketState 向量和状态滞回。
4. 将评分限制到 0–100，并把 RR 从基础评分剥离。
5. 建立统一 StructuralLevel 和唯一 EntryPlan。

### P2：持仓管理与验证体系

1. 重写为显式持仓状态机。
2. 加仓后完整重算风险和 R。
3. 轮动改为净 EV 决策。
4. 建立 point-in-time universe 和更细粒度成交回放。
5. 完成 walk-forward、压力测试和 8 周 shadow 验证。

## 12. 风险与约束

- 规则越多不代表 edge 越强；每增加一个 setup 或过滤器都必须有样本外增益证据。
- 只使用 Binance 公共历史接口可能无法恢复完整的历史 TopN、盘口和退市合约，需要增量自建数据仓。
- OI、long/short ratio、大户持仓的发布时间与 K 线时间必须严格对齐，否则容易产生前视偏差。
- 低流动性山寨币的固定滑点模型会严重低估成本。
- 分数只能用于排序和分层，不能替代止损风险和组合约束。
- 所有收益门槛都是研究晋级标准，不构成收益承诺或投资建议。

## 13. 待产品确认

以下不阻塞 PRD 评审，但实施前需要确认：

1. 主交易周期是否保持“4H 定方向、1H setup、15m 执行”。
2. BTC/ETH/SOL 是加入主池、独立池，还是仅作为系统性风险基准。
3. 可接受的账户最大回撤和单日损失预算。
4. 目标交易频率：低频高质量、还是中频轮动。

6. 是否建设长期 point-in-time 市场数据仓。
