| 项目 | 内容 |
|---|---|
| 文档版本 | V3.1 |
| 日期 | 2026-07-30 |
| 文档状态 | 已按范围落地，待模拟盘验证 |

## 0. 本期决策边界

### 0.1 本期只处理

1. 多头分数与空头分数完全相等时，当前逻辑因 `long_score >= short_score` 默认选择多头。
2. `regime`、`trend_state`、`risk_state` 的含义存在交叉，趋势、震荡、拥挤和风险可能混在一个标签中。
3. 震荡、拥挤和 BTC 极端波动等判断主要依赖固定阈值。
4. 普通行情状态缺少进入、退出和恢复确认，临界区可能频繁翻转。
5. 缺少明确的流动性状态。
6. 缺少统一的系统性风险状态。

### 0.2 本期明确不处理

- 不治理同源指标重复加分；
- 不修改 EMA、VWAP、布林带、KC、RSI、成交量、OI、资金费率等现有评分贡献；
- 不修改 `score_threshold`、`watch_threshold`；
- 不修改现有 8 分方向差要求；
- 不修改多空非同分时的评分选边逻辑；
- 不修改评分等级、入场质量和否决项权重；
- 不改变支撑压力、建议入场、开仓、止盈止损、加仓调仓和出场逻辑；
- 不引入机器学习模型；
- 不为单一币种配置专属参数。

### 0.3 防止系统继续复杂化

本期遵循以下约束：

1. 只新增一个精简的 `market_context`，不建立多层市场状态树。
2. `market_context` 只有四个独立状态字段，不增加“综合总状态”。
3. 所有状态共用一套滚动基线机制，不为每个指标开发不同的自适应算法。
4. 新状态只使用当前系统已有数据和一项必要的最优买卖价数据。
5. 新参数必须替换或淘汰旧固定阈值，配置项总数量不应增加。
6. 同分修复必须保证非同分信号结果不变。

## 1. 需求说明

### 1.1 改动背景

#### 1.1.1 多空同分默认多头

当前策略先计算多空分数，再通过以下条件选择方向：

```python
best_is_long = long_score >= short_score
```

当 `long_score == short_score` 时，系统会：

- 将多头选为最佳方向；
- 使用多头理由、否决项、结构类型和证据族；
- 设置 `direction=LONG`；
- 即使后续因方向差不足只输出 `WATCH`，下游仍可能把它展示或解释成多头候选。

该行为不代表市场确实偏多，只是代码比较符号造成的方向偏置。

#### 1.1.2 单一标签承载过多含义

当前状态主要分散在：

```text
regime
trend_state
risk_state
```

其中 `regime` 同时包含：

```text
TREND_LONG
TREND_SHORT
CHOP
OVERCROWDED
INSUFFICIENT_DATA
```

`OVERCROWDED` 属于参与者风险，不属于趋势方向；它与 `TREND_LONG/TREND_SHORT/CHOP` 放在同一个枚举中，会让一个字段同时回答两个问题：

1. 市场方向是什么；
2. 市场是否拥挤。

当趋势向上且多头拥挤时，真实状态应该同时成立，而不是由一个标签覆盖另一个标签。

#### 1.1.3 固定阈值

当前存在下列典型固定判断：

- EMA 间距相对价格的固定比例；
- 布林带宽度固定比例；
- 多空比固定上、下限；
- 资金费率固定上、下限；
- BTC 4H 固定 8% 振幅。

固定阈值的问题：

- BTC、ETH 与普通山寨币的常态波动不同；
- 同一币种在低波动和高波动阶段的常态不同；
- 同一固定值可能在某段行情过于敏感，在另一段行情又过于迟钝；
- 为修复失真继续增加币种特例，会导致参数越来越多。

#### 1.1.4 缺少状态滞回

当前部分状态由最新一根 K 线直接决定。指标在临界值附近波动时，可能出现：

```text
TREND_LONG → CHOP → TREND_LONG → CHOP
NORMAL → LONG_CROWD → NORMAL
```

这会造成：

- 信号方向和页面展示频繁变化；
- 自动开仓在状态边界附近反复等待或恢复；
- 策略更容易在噪声中追涨杀跌；
- 回测、模拟盘和实时运行对状态的解释不稳定。

#### 1.1.5 缺少流动性状态

当前已有成交额筛选，但没有统一的实时流动性状态。成交额合格不代表当前价差正常，也不代表行情数据仍然新鲜。

缺少流动性状态可能导致：

- 高分标的在价差突然扩大时仍进入开仓流程；
- 低流动性标的发生虚假突破；
- 预期入场价与实际成交价偏差明显；
- 历史 K 线信号正常，但实盘成交条件不合格。

#### 1.1.6 缺少系统性风险状态

当前存在 BTC 4H 极端波动过滤，但主要使用固定振幅，且数据请求失败时可能继续沿用缓存结果。

系统性风险不只表现为 BTC 固定百分比波动，还可能表现为：

- BTC 相对自身常态波动出现冲击；
- 标的池大量币种同时异常波动；
- 行情源过期，无法可靠判断市场风险；
- 全市场流动性在短时间内共同恶化。

### 1.2 改动点

#### R1：完全同分保持中性

当多空分数完全相等时：

```text
direction = NONE
candidate_action = NONE
direction_decision = TIE
```

动作规则：

| 同分分数 | 动作 |
|---|---|
| 低于现有观察阈值 | `NO_TRADE` |
| 达到现有观察阈值 | `WATCH` |
| 达到现有开仓阈值 | 仍为 `WATCH`，不得开仓 |

其他规则：

- 不选择多头或空头的 `setup_type`；
- 不因 `trend_state` 偏多或偏空重新推断评分方向；
- 明确记录 `long_score`、`short_score` 和 `TIE` 原因；
- 非同分信号继续使用现有逻辑；
- 同源评分、评分权重和评分阈值保持不变。

#### R2：建立精简行情上下文

新增一个 `market_context`，只包含：

```text
market_context
├─ direction_state
├─ crowding_state
├─ liquidity_state
├─ system_risk_state
└─ as_of
```

不提供第五个“综合状态”，避免再次把多种含义压缩为一个标签。

### 1.3 改动范围

#### 范围内

- 完全同分时的动作、方向、原因和接口字段；
- 趋势方向与拥挤风险拆分；
- 行情阈值的滚动基线；
- 普通状态进入/退出确认；
- 流动性状态；
- 系统性风险状态；
- 状态持久化、兼容输出、历史验证和模拟盘方案。

#### 范围外

- 同源评分和证据族重构；
- 任意指标评分加减；
- 非同分方向选择；
- 评分等级重新校准；
- 标的池改造；
- 建议入场位置和入场质量；
- 开仓、仓位和订单执行；
- 支撑位、压力位；
- 止盈止损；
- 加仓调仓；
- 出场逻辑。

## 2. 技术方案

### 2.1 R1：同分中性裁决

#### 2.1.1 裁决顺序

当前逻辑在判断同分之前就通过 `>=` 选出多头。新逻辑必须先处理同分：

```text
计算 long_score 和 short_score
        ↓
long_score == short_score ?
  ├─ 是：direction=NONE，禁止 ENTRY
  └─ 否：继续执行现有 best side 和方向差逻辑
```

建议伪代码：

```python
if long_score == short_score:
    return neutral_tie_signal(...)

best_is_long = long_score > short_score
# 以下继续使用现有非同分逻辑
```

#### 2.1.2 同分信号输出

```text
action: WATCH 或 NO_TRADE
direction: None
candidate_action: None
direction_decision: TIE
long_score: 原始多头分
short_score: 原始空头分
score: 与现有接口兼容，保留同分值
setup_type: 空
reason: long and short scores are tied; no directional edge
```

`long_score`、`short_score` 仅用于解释和测试，不参与新的评分计算。

#### 2.1.3 下游防回填

同分修复不能只修改 `strategy.py`。下游需要满足：

- 自动开仓必须同时要求 `action=ENTRY_*` 且 `direction` 非空；
- `candidate_action` 在同分时必须为空；
- API 明确输出 `direction=NONE`，不能省略后再由页面猜测；
- 页面优先使用显式 `direction`；
- 页面不得根据 `trend_state` 把同分信号重新显示为多头或空头；
- 可以同时展示“行情趋势偏多”和“评分方向同分”，二者含义不同；
- 同分不能参与按多头/空头候选数量的统计。

#### 2.1.4 保持不变的行为

- `long_score != short_score` 时结果与当前版本一致；
- 当前 8 分方向差仍然有效；
- 当前 WATCH/ENTRY 分数门槛不变；
- 当前评分原因、证据族、VWAP/EMA/布林/KC 等贡献不变；
- 当前否决规则不变。

### 2.2 R2：精简行情上下文

#### 2.2.1 状态定义

##### 方向状态

```text
direction_state:
  TREND_LONG
  TREND_SHORT
  RANGE
  UNKNOWN
```

只回答：当前行情方向是什么。

方向判断继续使用当前已经存在的价格结构和方向指标。EMA、VWAP、布林带和 KC 可以继续作为方向依据，但应汇总为一个方向结论，不生成四个对外状态。

##### 拥挤状态

```text
crowding_state:
  NORMAL
  LONG_CROWDED
  SHORT_CROWDED
  UNKNOWN
```

只回答：参与者是否在某一方向过度拥挤。

资金费率、多空比和已有参与者数据继续用于拥挤判断；拥挤状态：

- 不覆盖 `direction_state`；
- 不自动反转交易方向；
- 不作为新的正向评分；
- 同向拥挤时保留现有否决或限制语义。

##### 流动性状态

```text
liquidity_state:
  NORMAL
  THIN
  UNKNOWN
```

只回答：当前是否具备基本开仓成交条件。

##### 系统性风险状态

```text
system_risk_state:
  NORMAL
  STRESS
  UNKNOWN
```

只回答：当前是否允许新增整体风险。

#### 2.2.2 不设置综合总状态

允许以下组合同时存在：

```text
direction_state = TREND_LONG
crowding_state = LONG_CROWDED
liquidity_state = NORMAL
system_risk_state = STRESS
```

含义为：

> 趋势向上，但多头拥挤且系统性风险异常。

系统不能把它压缩成 `OVERCROWDED`、`RISK` 或其他单一标签；下游必须分别读取对应字段。

### 2.3 自适应阈值

#### 2.3.1 设计原则

本期不开发复杂的参数优化器，只引入一套共享滚动基线：

```text
当前值
  → 与该标的最近一段已完成历史比较
  → 得到相对位置或标准化结果
  → 使用统一进入/退出边界
```

推荐优先使用滚动中位数和分位位置，原因是：

- 对极端尖峰不如均值敏感；
- 容易解释；
- 不需要为每个币拟合模型；
- 可以被行情、拥挤、流动性和系统风险复用。

#### 2.3.2 各状态使用的最少输入

| 状态 | 核心输入 | 自适应方式 |
|---|---|---|
| `direction_state` | EMA 间距/ATR、通道宽度/ATR、现有方向一致性 | 与该标的历史分布比较 |
| `crowding_state` | 资金费率、多空比 | 与该标的滚动中位数和极端分位比较 |
| `liquidity_state` | 24H 成交额、最优买卖价差 bps | 与自身滚动中位数比较，并保留最低安全底线 |
| `system_risk_state` | BTC 4H 变动/ATR、标的池异常波动比例 | 与 BTC 自身常态和标的池常态比较 |

说明：

- EMA、VWAP、布林和 KC 对评分的现有影响本期不变；
- 本表只规定状态判断如何避免使用固定绝对比例；
- 不为每个指标单独增加牛市、熊市、月份或币种参数；
- 进入/退出分位值是待校准参数，PRD 不直接指定生产常量。

#### 2.3.3 冷启动与数据不足

- 历史样本不足时，对应状态输出 `UNKNOWN`；
- 影子阶段可以同时记录旧固定阈值结果用于对比；
- 未完成校准前不能假设 `UNKNOWN=NORMAL`；
- 流动性或系统性风险为 `UNKNOWN` 时，生产接管阶段默认禁止新开仓；
- 所有滚动统计只使用当时已经完成的数据，禁止未来数据。

### 2.4 状态滞回

#### 2.4.1 普通方向与拥挤状态

采用“进入边界、退出边界、连续确认”三项机制：

```text
进入新状态：
  达到较严格进入边界
  ＋连续 2 根指定周期已收盘 K 线成立

退出当前状态：
  回落到较宽松退出边界
  ＋连续 2 根指定周期已收盘 K 线成立
```

约束：

- 方向状态以已收盘 4H K 线为主；
- 盘中价格不能直接翻转确认方向；
- 未确认期间保留当前状态，同时标记 `pending`；
- 从多头趋势切换为空头趋势也必须完成确认；
- 同一根 K 线中，同一状态最多确认变化一次。

#### 2.4.2 流动性与系统性风险

风险状态采用“快速进入、慢速恢复”：

```text
NORMAL → THIN/STRESS：
  一次严重风险命中即可立即进入

THIN/STRESS → NORMAL：
  回到退出边界
  ＋连续 2 次健康检查
```

原因：

- 风险出现时应优先保护账户；
- 风险刚消失的一次检查可能只是短暂恢复；
- 不需要为风险状态建立更多中间等级。

#### 2.4.3 状态持久化

每个状态只保存：

```text
current
pending
confirm_count
changed_at
as_of
```

进程重启必须恢复上述字段，不能因重启将状态直接重置为 `NORMAL`。

### 2.5 流动性状态

#### 2.5.1 输入

只使用三项基础信息：

1. 24H 成交额；
2. 最优买价和最优卖价计算的实时价差 bps；
3. 数据更新时间。

计算：

```text
spread_bps = (best_ask - best_bid) / mid_price × 10,000
volume_ratio = current_quote_volume_24h / rolling_median_quote_volume_24h
```

#### 2.5.2 状态规则

| 条件 | 状态 | 新开仓 |
|---|---|---|
| 成交额与价差均正常，数据新鲜 | `NORMAL` | 可继续后续判断 |
| 成交额显著衰减或价差异常扩大 | `THIN` | 禁止 |
| 买卖价、成交额或时间戳缺失/过期 | `UNKNOWN` | 禁止 |

约束：

- 流动性只决定能否开仓，不改变趋势方向；
- 高评分不能抵消 `THIN/UNKNOWN`；
- 本期不加入多档盘口深度和复杂冲击成本模型；
- 后续只有实际滑点证明三项输入不足时，才单独评估新增指标。

### 2.6 系统性风险状态

#### 2.6.1 输入

只使用两类风险：

1. BTC 4H 冲击：
   - 4H 实体变化或振幅相对 BTC 4H ATR；
   - 替代单一固定 8% 判断。
2. 标的池共振：
   - 同一时点出现异常波动的合格标的比例；
   - 防止只观察 BTC 而忽略全市场共同恶化。

数据源无法更新或超出允许缓存时间时，输出 `UNKNOWN`。

#### 2.6.2 状态规则

| 条件 | 状态 | 新开仓 |
|---|---|---|
| BTC 与标的池均处于正常范围 | `NORMAL` | 可继续后续判断 |
| BTC 冲击或标的池大范围异常 | `STRESS` | 禁止新增合约风险 |
| 关键数据缺失、过期或无法计算 | `UNKNOWN` | 禁止新增合约风险 |

`STRESS/UNKNOWN` 期间：

- 允许止损、止盈、减仓和平仓；
- 禁止新开仓和增加总风险；
- 不自动强平现有仓位；
- 是否触发主动减仓由后续出场/组合风险 PRD 决定。

### 2.7 状态与交易流程关系

```text
market_context
  ├─ direction_state：提供行情方向背景
  ├─ crowding_state：提供同向拥挤否决
  ├─ liquidity_state：THIN/UNKNOWN 否决新开仓
  └─ system_risk_state：STRESS/UNKNOWN 否决新增风险
             ↓
现有多空评分保持不变
             ↓
完全同分 → 中性 WATCH/NO_TRADE
             ↓
非同分 → 继续现有方向差、入场质量和否决流程
```

状态不通过加减分表达，避免高分抵消风险。

### 2.8 相比当前逻辑的改善

| 当前逻辑 | 本期方案 | 解决的问题 |
|---|---|---|
| `long_score >= short_score` | 同分先返回中性 | 消除完全同分的多头偏置 |
| 同分 WATCH 仍可能携带多头方向 | 显式 `direction=NONE`、`candidate_action=None` | 防止下游重新解释为多头 |
| `regime` 同时表达趋势和拥挤 | 方向、拥挤拆成独立字段 | 一个标签不再承载多种含义 |
| 趋势和拥挤只能二选一 | 多个真实状态可以同时存在 | 保留“趋势向上且多头拥挤”等信息 |
| EMA/BOLL/资金费率/多空比使用固定边界 | 统一使用滚动基线和相对位置 | 减少跨币种、跨阶段失真 |
| 单根 K 线可改变普通状态 | 双边界＋连续确认 | 降低临界区频繁翻转 |
| 只有成交额筛选 | 成交额＋实时价差＋数据新鲜度 | 补齐开仓前流动性风险 |
| BTC 固定 8% 过滤 | BTC ATR 冲击＋标的池共振 | 提高系统风险适应性 |
| 数据取不到可能继续使用旧安全结果 | 超时后明确 `UNKNOWN` 并禁止新增风险 | 防止陈旧数据被当成正常 |
| 风险可能通过评分间接表达 | 风险状态使用硬否决 | 高分不能覆盖流动性和系统风险 |

### 2.9 输出字段

建议新增：

```text
direction                 LONG / SHORT / NONE
direction_decision        LONG_WINS / SHORT_WINS / TIE
long_score
short_score

market_context:
  direction_state
  crowding_state
  liquidity_state
  system_risk_state
  as_of
```

只为内部诊断保存：

```text
pending
confirm_count
changed_at
baseline_status
```

内部诊断字段不进入常规页面，避免增加展示复杂度。

### 2.10 验收标准

#### 同分裁决

- `long_score == short_score` 时，100% 输出 `direction=NONE`；
- 同分无论分数多高都不得输出 `ENTRY_LONG/ENTRY_SHORT`；
- 同分时 `candidate_action=None`；
- 同分时页面不能显示“建议做多”或“建议做空”；
- 多空镜像测试结果对称；
- 黄金样本中所有非同分信号的动作、分数、方向和原因与旧版本一致；
- 本期评分权重、证据族和同源指标结果无变化。

#### 行情状态

- `OVERCROWDED` 不再覆盖趋势方向；
- 四个状态字段必须分别输出；
- 缺数时明确为 `UNKNOWN`，不得静默使用 `NORMAL`；
- 所有滚动统计通过无未来数据测试；
- 单根普通 K 线不能确认趋势翻转；
- 风险恶化可以立即进入，恢复必须连续确认；
- 进程重启后状态和确认计数保持一致；
- `liquidity_state=THIN/UNKNOWN` 时禁止新开仓；
- `system_risk_state=STRESS/UNKNOWN` 时禁止新增风险；
- 高分不能绕过流动性或系统风险状态。

#### 复杂度

- 不新增评分维度；
- 不修改评分参数；
- 不新增综合总状态；
- 不出现单币参数；
- 自适应阈值使用同一滚动基线实现；
- 新配置项应替换旧固定阈值，配置项总量不得增加。

#### 策略验证

影子运行报告至少包含：

- 同分信号数量及多空展示变化；
- 各状态持续时间和切换次数；
- 滞回前后状态翻转次数；
- 流动性与系统风险拦截次数；
- 被拦截交易的后续表现；
- 手续费后净期望值、胜率、盈亏比、最大回撤；
- 状态 `UNKNOWN` 的发生率和持续时间。

不能只因胜率提高就上线；若净期望值、回撤或风险暴露变差，应继续保持影子状态。

## 3. 兼容性问题

### 3.1 `StrategySignal` 兼容

当前 `direction` 已允许为空，因此同分中性不需要新增 `PositionSide` 枚举。

需要确认：

- 所有调用方都能接受 `direction=None`；
- 序列化时显式输出 `"NONE"`，而不是缺省字段；
- `candidate_action` 为空时不会进入自动开仓；
- 任何方向推断都不能覆盖 `direction_decision=TIE`。

### 3.2 旧状态字段兼容

第一阶段保留：

```text
regime
trend_state
risk_state
```

同时影子输出 `market_context`。

接管顺序：

1. 页面和日志先读取新字段；
2. 自动开仓再读取流动性和系统风险；
3. 已有持仓逻辑保持旧字段；
4. 一个稳定发布周期后再评估旧字段下线；
5. 不允许新旧状态逻辑长期同时决定订单。

### 3.3 `regime=OVERCROWDED`

兼容期内旧字段可以继续输出 `OVERCROWDED`，但新逻辑必须同时保留真实 `direction_state`。

新调用方不得再把 `OVERCROWDED` 当作方向。旧字段下线后：

- 方向只读取 `direction_state`；
- 拥挤只读取 `crowding_state`。

### 3.4 页面兼容

页面需要区分：

```text
行情方向：趋势偏多
评分方向：同分，无交易优势
```

不能因为行情方向偏多，就把评分同分显示成“多头候选”。

### 3.5 历史与模拟盘兼容

- 旧历史结果保留旧状态，不追溯改写；
- 新回测保存当时的滚动基线，不使用未来样本；
- 缺少历史买卖价差时，流动性状态标为 `UNKNOWN`；
- 流动性历史不完整的回测不能直接与实盘等价；
- 已有持仓不因新状态字段追溯修改开仓理由或出场规则。

## 4. 风险点

| 风险点 | 可能影响 | 控制方式 |
|---|---|---|
| 下游继续从趋势推断方向 | 同分仍被展示成多头/空头 | 显式 `direction_decision=TIE`，页面优先级测试 |
| 非同分行为被误改 | 信号数量和策略行为超出范围变化 | 黄金样本回归，要求非同分结果完全一致 |
| 滚动样本不足 | 状态长期 `UNKNOWN` | 设置最低历史长度，影子期统计覆盖率 |
| 自适应阈值过度拟合 | 历史表现好、样本外失效 | 统一机制、禁止单币参数、走步验证 |
| 滞回造成方向延迟 | 错过快速趋势初段 | 风险状态即时生效；不增加低周期补偿参数 |
| 流动性门过度敏感 | 正常机会被大量拦截 | 记录价差原值和被拦截交易，不直接放宽 |
| 行情数据断连 | 大量状态变为 `UNKNOWN` | 明确超时时间、健康监控；风险上保持失败关闭 |
| 系统风险门过度保守 | 错过恐慌后的反弹 | 恢复采用连续确认，统计机会成本 |
| 标的池样本过少 | 共振比例失真 | 样本不足时 `UNKNOWN`，不强行计算 |
| 状态组合增多 | 下游逻辑分支增加 | 只允许四个固定字段，不增加综合状态和中间等级 |
| 旧字段长期存在 | 两套解释产生冲突 | 设定迁移周期和删除条件 |
| 只看胜率优化阈值 | 小赚大亏或交易过少 | 同时评估净期望、盈亏比、回撤和样本数 |

## 5. 改动计划

本节记录实施计划；P1-P6 已按本 PRD 范围完成代码落地，P7-P8 仍需在模拟盘验证后决定。

| 阶段 | 工作内容 | 交付物 | 完成条件 |
|---|---|---|---|
| P0 基线冻结 | 固定当前代码和代表性信号样本 | 同分与非同分黄金样本 | 可复现同分默认多头 |
| P1 同分修复 | 同分中性、显式方向决策、下游防回填 | 单元测试、API/UI 测试 | 同分不产生方向，非同分完全回归 |
| P2 状态拆分影子版 | 新增四个独立状态，旧状态继续运行 | 新旧状态对比日志 | 趋势与拥挤可同时表达 |
| P3 自适应阈值 | 统一滚动基线，替换固定行情阈值 | 基线快照、无未来测试 | 跨阶段结果稳定，无单币特调 |
| P4 状态滞回 | 加入进入、退出、连续确认和持久化 | 边界测试、重启测试 | 单根 K 线不造成普通状态翻转 |
| P5 风险状态影子版 | 流动性和系统风险只记录不拦截 | 拦截影响报告 | 数据覆盖率与误拦截可接受 |
| P6 模拟盘接管 | 风险状态开始否决模拟盘新开仓 | 模拟盘 A/B 报告 | 样本数和风险指标通过评审 |
| P7 灰度上线 | 统一切换下游并保留回滚开关 | 上线与回滚清单 | 不存在新旧状态共同决定订单 |
| P8 清理 | 下线旧混合字段和已替代固定阈值 | 删除清单 | 配置项总量不增加 |

### 5.1 推荐实施顺序

同分修复可以单独交付，因为：

- 逻辑边界明确；
- `direction` 已支持空值；
- 不依赖新行情状态；
- 容易用非同分回归测试控制影响范围。

行情状态必须先影子运行，再启用风险否决，不能与同分修复一次性接管全部订单行为。

### 5.2 回滚原则

- 同分修复和行情状态分别设置开关；
- 风险状态影子期不改变订单；
- 灰度期可立即恢复旧状态读取；
- 回滚保留当时输入、滚动基线和状态变化记录；
- 回滚不追溯修改已有持仓。

## 8. 最终决策摘要

1. 本期评分只修完全同分默认多头。
2. 同分输出 `direction=NONE`，无论分数多高都不得开仓。
3. 非同分评分、同源指标、权重、阈值和 8 分方向差全部保持不变。
4. 行情使用方向、拥挤、流动性和系统风险四个独立状态。
5. 不再增加综合总状态，也不允许拥挤覆盖趋势。
6. 固定行情阈值逐步替换为统一滚动基线，不为单币调参。
7. 普通状态使用进入/退出边界与连续确认；风险状态快速进入、慢速恢复。
8. 流动性异常或未知时禁止新开仓。
9. 系统性风险异常或未知时禁止新增风险，但不自动处理已有仓位。
10. 本 PRD 已按用户后续指令落地；未授权同源评分、权重、入场、仓位、止盈止损、加仓调仓和出场等范围外改动。
